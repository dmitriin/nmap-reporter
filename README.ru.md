# nmap-reporter

[English](README.md) · [Русский](README.ru.md)

Превращает XML-сканы Nmap в аккуратные HTML-отчёты за секунды.

`nmap-reporter` парсит XML-файл Nmap (`nmap -oX`) и генерирует самодостаточный HTML-отчёт: сводка по хостам, таблицы портов по каждому хосту и базовые рекомендации по безопасности для типовых открытых сервисов.

## Зачем

Пентестеры и системные администраторы запускают Nmap постоянно, но превращение сырого XML в читаемый отчёт для клиента или тикета требует ручной работы. `nmap-reporter` делает это одной командой — без сервера, без базы данных и без зависимостей кроме одного бинарника.

## Установка

 go install github.com/yourname/nmap-reporter@latest

Или сборка из исходников:

 git clone https://github.com/yourname/nmap-reporter.git
 cd nmap-reporter
 go build -o nmap-reporter .

## Использование

 nmap -sV -oX scan.xml 127.0.0.1
 nmap-reporter -input scan.xml -output report.html

Флаги:

| Флаг | По умолчанию | Описание |
| ------ | -------------- | ---------- |
| `-input` | (обязателен) | Путь к Nmap XML (`-oX`) |
| `-output` | `report.html` | Путь к выходному файлу |
| `-lang` | `en` | Язык отчёта: `en` или `ru` |

Примеры:

# Английский отчёт (по умолчанию)

 nmap-reporter -input scan.xml -output report-en.html

# Русский отчёт

 nmap-reporter -input scan.xml -output report-ru.html -lang ru

## Что в отчёте

- Сводка по хостам: IP, hostname, статус, количество открытых портов.
- Таблица по каждому хосту: порт, протокол, состояние, сервис, версия.
- Рекомендации по типовым открытым сервисам (SSH, RDP, SMB, Redis и т.д.).

## Расширения (Open Core)

Ядро распространяется под MIT и остаётся бесплатным. Дополнительный функционал поставляется отдельными исполняемыми файлами, которые ядро находит через `PATH`:

- `nmap-reporter-docx` — DOCX-отчёты с корпоративными шаблонами (проприетарный).
- `nmap-reporter-cloud` — синхронизация отчётов и шаблоны команды (проприетарный, в планах).

Если в `PATH` найден `nmap-reporter-<name>`, ядро передаёт управление ему:

 nmap-reporter docx -input scan.xml

Ядро никогда не зависит от расширений — они опциональны.
